Kafka Outbound Backpressure & Workflow Isolation

A memory-aware backpressure mechanism that keeps the JVM stable during high-volume Kafka outbound processing, especially with large payloads.

  • Byte-based admission control using estimated message memory footprints, configurable in-flight byte budgets and concurrency limits to stop uncontrolled accumulation in memory.
  • Adaptive concurrency with AIMD (additive increase, multiplicative decrease) that regulates outbound capacity from JVM heap utilization, processing errors and system health.
  • Workflow-level isolation by workflowId and stageId with independent resource quotas, so a slow downstream integration cannot affect unrelated workflows.
  • Load tested across payload sizes and concurrency levels, analyzing throughput, heap consumption and Kubernetes pod memory to tune stability under load.
